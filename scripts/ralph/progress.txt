## Codebase Patterns
- Prisma schema uses multi-file layout in `packages/db/prisma/schema/` — each domain gets its own `.prisma` file
- IDs use `@default(cuid(2))` across all models
- Table names use `@@map("snake_case")` convention
- Foreign keys get `@@index([fieldName])` declarations
- Relations use `onDelete: Cascade` for user-owned entities
- Project uses `db:push` (no migration files) — validate schema with `prisma generate`
- Pre-existing typecheck error: `web-push` module lacks type declarations (not blocking)
- oRPC routers: plain objects in `packages/api/src/routers/`, registered in `routers/index.ts` appRouter
- Use `protectedProcedure` for auth routes, access userId via `context.session.user.id`
- Turbo task for typechecking is `check-types` (not `typecheck`)
- TanStack Router route tree (`routeTree.gen.ts`) is generated by the vite plugin at build time; to regenerate manually, run `pnpm vite build` from `apps/web/` (the `@tanstack/router-cli generate` command alone may not work); delete `routeTree.gen.ts` first to force regeneration
- Settings pages go in `apps/web/src/routes/_auth/settings/` — add nav items in the parent `settings.tsx` layout
- oRPC client queries use `useQuery(orpc.<router>.<procedure>.queryOptions())` and mutations use `useMutation` with `orpc.<router>.<procedure>.call(input)` + `queryClient.invalidateQueries`
- Dialog component uses Base UI (`@base-ui/react/dialog`), not Radix — `DialogTrigger` uses `render` prop for custom trigger elements
- WebSocket: use `@hono/node-ws` with `createNodeWebSocket({ app })` → get `upgradeWebSocket` and `injectWebSocket`; must call `injectWebSocket(server)` after `serve()`
- WebSocket types: use `WSContext` from `hono/ws` (not `ServerWebSocket`) for the ws parameter in handlers
- WebSocket route must be registered before CORS middleware to avoid upgrade issues
- `packages/shared/` follows same pattern as `packages/db/` — exports via `./src/index.ts`, uses `@myagents/config/tsconfig.base.json`
- Zod v4 `z.record()` requires two arguments: `z.record(z.string(), z.unknown())` (not single-arg like v3)
- Prisma `Json` fields require `InputJsonValue` type — convert `Record<string, unknown>` via `JSON.parse(JSON.stringify(obj))`
- Prisma enum types in oRPC handler return values cause TS2742 errors — serialize enums to strings (e.g., `String(agent.type)`) to avoid type portability issues
- In JSX with `Record<string, unknown>` data: use `String(val)` not `val as string`, and use ternary `val ? <JSX/> : null` instead of `val && <JSX/>`
- Use `select` over `include` in Prisma queries within oRPC routes to control return shape and prevent type leakage
- Compound unique constraints can be used for lookups: `prisma.agent.findUnique({ where: { userId_slug: { userId, slug } } })`
- oRPC `queryOptions` for procedures with required input needs `{ input: { ... } }` wrapping; optional input procedures can pass input directly
- When converting a leaf route to a layout route (e.g., `agents.tsx` → layout with `<Outlet />`), move the page content to `agents/index.tsx` and create child routes as `agents/$param.tsx`
- Cast oRPC response data to `Record<string, unknown>` in UI components when the inferred return type is narrow — access fields via `String(data.field)` pattern
- WebSocket client hook: `useWebSocket()` in `apps/web/src/hooks/use-websocket.ts` — provides `sendFrame(method, payload)`, `subscribe(handler)`, `connected` state; auto-reconnects
- WebSocket URL: replace `http` with `ws` in `VITE_SERVER_URL` + `/ws`; auth via session cookie (no explicit auth needed)
- TanStack Router has no `useOutletContext` — use React context to pass state from layout routes to children
- To regenerate `routeTree.gen.ts`: run `npx vite build` from `apps/web/` (router plugin triggers during build)
- `.js` build artifacts in `apps/web/src/` conflict with `.tsx` source files for route generation — delete `.js` files before regenerating route tree
- Bottom nav items in `apps/web/src/components/bottom-nav.tsx` — add `{ to, label, icon }` entries to `navItems` array
- API key auth for HTTP: `packages/api/src/context.ts` supports `Authorization: Bearer <key>` header as alternative to session cookies — CLI clients use this
- WebSocket supports client connections with API key: `?type=client&apiKey=...` query params
- oRPC HTTP wire format: POST to `/rpc/<router>/<procedure>` with JSON body
