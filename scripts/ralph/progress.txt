## Codebase Patterns
- Agent registration uses `agent.register` WebSocket frame; server upserts via `handleAgentRegister()` in `apps/server/src/ws.ts`
- CLI stores agent overrides (name, description, timeout) in `~/.myagents/agents.yaml` via `apps/cli/src/agent-config.ts`
- `mergeYamlOverrides()` runs before registration to apply local YAML values to detected agents
- Server pushes config changes to CLI via `agent.configUpdate` frame; CLI saves to YAML via `updateAgentConfig()`
- Pre-existing typecheck errors in server: `openclawAgentId` property and `web-push` missing types — not introduced by this work
- Admin route protection: use `beforeLoad` with `context.session.user.role !== "admin"` redirect; use `adminProcedure` for API
- App-wide settings stored in `AppSetting` key-value table; fetch via `orpc.settings.getAll`, update via `orpc.settings.update`
- `orpc.appConfig` returns a computed client-safe config object (smtpConfigured, ssoEnabled, signupsDisabled, etc.)
- Messages rendered via `localMessages.map(msg => <MessageBubble>)` in `conversations/$id.tsx`; filter display-only via `.filter()` before `.map()`
- Tailwind prose classes require `@tailwindcss/typography` plugin — added via `@plugin "@tailwindcss/typography"` in `globals.css`
- `agentSelect` in `packages/api/src/routers/agents.ts` controls which Agent fields are returned to the client — add new fields here
- `updateMutation` in agent settings has an explicit type annotation on `mutationFn` — update it when adding new fields to the update API
- Delete confirmation uses Dialog (not AlertDialog — component doesn't exist) with type-to-confirm pattern; see `_auth/conversations.tsx` for reference
- Use `orpc.<router>.key()` for broad cache invalidation across all queries in a namespace
- New frame methods must be added to `FrameMethod` enum in `packages/shared/src/frames.ts`
- In-memory server state (Maps) in `ws.ts` is the pattern for transient data with TTLs; DB is for persistent data
- `handleAgentRegister` in ws.ts is the hook point for actions when an agent reconnects (fires after agent status → online)

## 2026-03-20 - OPT-007
- **What was implemented:** Added in-memory message queue for offline agents. When a user sends a message to an agent whose CLI is disconnected, the message is saved to DB and queued in memory with a 5-minute TTL. When the CLI reconnects (via `handleAgentRegister`), queued messages are delivered in order. If TTL expires, user is notified via `queue.expired` WebSocket event and an error message is saved to the conversation. The UI shows a "Pending delivery — agent offline" indicator on queued messages.
